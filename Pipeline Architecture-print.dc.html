Interpret

The model resolves the request into a structured spec — system, part type, dimensions, constraints — and asks a clarifying question when confidence is low.

3

Author OpenSCAD

spec → .scad source

The spec becomes real, parametric OpenSCAD — via one of two routes:

● Library route · default

Known systems call vetted parametric libraries with the params. Deterministic, fast, guaranteed-valid.

● Freeform route · novel shapes

No library fits → Claude writes original SCAD, grounded on the OpenSCAD cheatsheet.

UI · OpenSCAD code panel (now live + editable)
4

Render

.scad → mesh + STL

OpenSCAD-WASM compiles in the browser: an F5 preview feeds the live Three.js viewer; F6 produces the manifold mesh exported as STL. Heavy parts can fall back to a server renderer.

UI · 3D viewer UI · Download STL
5

Validate & self-correct

agent loop

Checks manifoldness, wall thickness, overhangs and bed fit. On a compile error or failed check, the diagnostics go back to step 3 — Claude patches the SCAD and re-renders until it passes.

↺
repair loop — render error / bad geometry → re-author → re-render. Capped at N tries, then surfaces a fixable explanation.
6

Deliver & tune

printable + adjustable

Spec params become the parameter sliders — each change re-runs steps 3–4 for a live re-render. The validated STL downloads or publishes to MakerWorld with its parametric source attached.

Two decisions that shape the build
Library-first, freeform-fallback

Route to curated libraries whenever a system matches — they're safe, instant, and standards-compliant. Reserve LLM-authored SCAD for genuinely novel parts, where the repair loop earns its keep.

WASM in-browser vs. server render

WASM keeps it instant, private and offline for typical parts; a server renderer handles heavy CSG, caches common library calls, and keeps the agent repair loop off the user's device.
